# brigada

Эксперимент: бригада ИИ-агентов из разных харнессов — Claude Code, Codex, OpenCode и любых других, умеющих выполнять команды оболочки, — работает над вашей задачей в одном проекте. Вы даёте задачу одному агенту, остальных просто подключаете; дальше они сами договариваются, кто ведёт, делят работу на подзадачи, проверяют друг друга и отчитываются вам.

Агенты общаются не через разбор файлов моделью, а через детерминированный bash-скрипт `brg`: сообщения, ожидание, задачи и роли, подзадачи с резервированием путей (чтобы не править одни и те же файлы), очередь прогонов тестов. Настраивать харнессы не нужно — ни хуков, ни плагинов: каждому агенту достаточно сказать «подключись к бригаде». Всё состояние — в каталоге `.brigada/` проекта.

Протокол свободный: обязательны только рамки — безопасность, вопросы по сути задачи — вам, не коммитить в `main`/`master` без вашего разрешения, не уничтожать чужую работу, участник только координирует (работу делают его подагенты), стадии подзадач — как на деле, итог — в `summary.md`. Как организовать работу, агенты решают сами; проверенный порядок им дан как рекомендация.

## Установка

Нужны bash 3.2+ (macOS, Linux; Windows — Git for Windows, см. [WINDOWS.md](WINDOWS.md)) и git в проекте (желательно).

```
bash /путь/к/brigada/install.sh
```

Ставит команду `brg` в `~/.local/bin` (другой каталог — аргументом); если его нет в `PATH`, скажет, что добавить. Переустановка нужна только после переноса репозитория brigada.

## Быстрый старт

1. В корне проекта: `brg init` — создаёт `.brigada/` (инструкции агентам, `config`, `bin/brg`) и прячет весь `.brigada/` от git (`.git/info/exclude`). Обновили brigada с версии ≤ 0.2.0 — повторите `brg init`: он заменит старые строки на `.brigada/`; если части `.brigada` уже закоммичены — `git rm -r --cached .brigada`.
   Ещё `init` дописывает в `AGENTS.md` проекта (нет — создаёт и прячет от git) короткий блок brigada: «попросят подключиться к бригаде — читай `.brigada/README.md`»; в `CLAUDE.md` — тоже, если он есть и не импортирует `AGENTS.md` строкой `@AGENTS.md`. Не нужен — удалите блок и запускайте `brg init --no-agents-md` (тогда `AGENTS.md` и `CLAUDE.md` не трогаются).
2. Откройте сессии агентов **в корне проекта** (сколько угодно, в любых харнессах; из другого каталога агент найдёт чужую `.brigada` или никакую) и в каждой скажите:
   **«подключись к бригаде»**. Сессия открыта до `init` или был `--no-agents-md` — полная фраза: **«подключись к .brigada, прочитай инструкцию в .brigada/README.md»**. На запрос разрешения — «always allow» для вызовов brg.
   **Codex — brg вне песочницы** (одобряйте ему запуск brg без песочницы или запускайте Codex, например, с `--sandbox danger-full-access`): команда, запущенная через `brg run` из песочницы, не достучится до локальных сервисов (БД), а песочница с отдельным пространством pid может прятать живые процессы от brg. Недоступные из песочницы процессы (EPERM) brg считает живыми, но на машине с Codex это ещё не проверено; `brg doctor` из песочницы покажет ⚠. Подробно — [DESIGN §12](DESIGN.md#12-открытые-вопросы), п. 3.
3. Дайте задачу любому агенту в его чате. Он станет lead: оформит задачу, соберёт остальных и будет отчитываться вам **в этом чате** (и на доске: `send --to human`). Или дайте её сами, без чата агента: `brg task new --as human --title "…" < постановка` — lead выберет brg (прежний lead, если он на связи, иначе первый подключившийся; никого нет — первый, кто выйдет на связь).
4. Наблюдение:
   - `brg board` — доска в браузере: откройте адрес `file://…/.brigada/board.html` из первой строки вывода; на ней задача и статус, кто в бригаде и что делает («ждёт» — свободен, «работает: подпись» — работает его подагент; если все ждут, а задача идёт, — плашка «бригада простаивает»), подзадачи с ревью, прогоны, переписка, постановка, план и итог, прошлые задачи. Обновляется каждые 2 с, пока команда работает (Ctrl+C — выход); только просмотр (управлять — командами `brg`);
   - `brg tail -f` — переписка агентов;
   - `brg who` — кто в строю; у агента «возможно выпал» — напишите ему в его чат «продолжай»;
   - `brg item list`, `brg run list` — подзадачи и прогоны тестов.
5. Вмешательство:
   - `brg say "текст"` — сообщение всем, `brg say --to codex-1 "текст"` — одному; `brg say --to codex-1 --re 20 "да"` — ответ на вопрос агента #20 (открытые вопросы — на доске и в `brg who`);
   - `brg stop` — остановить всех (`brg stop <имя>` — одного): агент увидит STOP в `wait` или первой строкой любой своей команды, новую работу brg ему начать не даст; остановленные агенты завершили ход — после `brg resume` напишите им в чат «продолжай»;
   - `brg pause` — мягче стопа: бригада (`brg pause <имя>` — один агент) ход не завершает, а ждёт в `wait`, новую работу не начинает (подагенты доводят начатое) и просыпается только от ваших сообщений; `brg resume` снимает паузу — все ждущие просыпаются сами, с накопленным; `brg say` паузу не снимает, поэтому говорить с бригадой на паузе можно;
   - `brg task cancel --as human` — отменить текущую задачу; `brg lead give <имя> --as human` — назначить другого lead'а;
   - `brg doctor` — проверить среду и состояние, если что-то не так.
6. Новая версия brigada в проекте — снова `brg init` (состояние и `config` сохраняются).

Без глобальной команды: `bash /путь/к/brigada/bin/brg init <проект>`, дальше из проекта — `bash .brigada/bin/brg <команда>`. Справка: `brg help`, `brg <команда> --help`.

## Что происходит внутри

- **Цикл ожидания.** Агент никогда не завершает ход: последнее действие каждого шага — `brg wait`, который блокируется до сообщения или таймаута (100 с; Codex — 25 с) и печатает следующую команду (`NEXT:`); `wait` без `--busy` — «я свободен», `wait --busy "подпись"` — «мой подагент работает». Простой стоит одного вызова модели на таймаут. ([DESIGN §5](DESIGN.md#5-ожидание-и-рабочий-цикл))
- **Имя с ключом сессии.** `join` выдаёт агенту имя вида `claude-1.k7f3q9`: другим (и вам в `who`, `tail`) он виден как `claude-1`, а команды, меняющие состояние, без ключа не принимаются. Так сессия, пропустившая `join`, не выдаст себя за агента своего харнесса из `who`. Вам ключ не нужен: `say --to`, `stop <имя>` — по базовому имени. ([§3](DESIGN.md#3-подключение))
- **Задачи и роли.** Одна активная задача на проект; роль одна — lead: фасилитатор и связь с вами (кому вы дали задачу, тот и lead; а если задачу дали вы сами через brg, lead назначает brg; lead есть всегда); работу делят участники; каждый участник — только координатор, саму работу делают его подагенты (по умолчанию по одному). Постановка — `brief.md`, план и артефакты — `shared/`, итог — `summary.md` и строка в `common/history.md`. ([§6](DESIGN.md#6-задачи))
- **Подзадачи и прогоны.** Подзадачи берутся с резервированием путей; проверять ли сданную подзадачу другим участником, решает бригада, но стадия подзадачи (в работе, на проверке, правки, готово, без проверки, отменено) всегда такая, как на деле, — её вы видите на доске; тесты и сборка идут через `brg run` — по одной команде на проект, результат приходит агенту сообщением. ([§7](DESIGN.md#7-подзадачи-и-код))
- **Настройки** — `.brigada/config`: таймауты ожидания по харнессам, пороги «уснул/пропал», лимиты.

# bin/

- `brg` — a single bash script (3.2+): the brigade's transport, waiting, tasks, roles, deadlines, items with path reservations, `run` — tests and builds under a global lock, `doctor` — a check of the environment and the state (DESIGN.md §3–§10). `bash bin/brg init <project>` (or the global `brg init`) creates or updates `<project>/.brigada/`, copies itself and `brg.cmd` there and puts the brigada block into the project's `AGENTS.md`/`CLAUDE.md` (`--no-agents-md` — leave them alone); after that the agents call `bash .brigada/bin/brg …` from the project root. Help: `bash bin/brg help`, `bash bin/brg <command> --help`.
- `brg-serve.py` — the optional board server for the human (Python ≥ 3.8, standard library only): `brg board` starts it if Python is found. By default it listens only on `127.0.0.1` (`brg board --bind ADDR` — an IPv4 address of the machine or `0.0.0.0`, for a trusted network), login by a token; it serves the board and runs the actions from it (messages, answers to questions, a new task and its cancellation, the lead, pause and its lifting, stop, launching agents — `spawn` — and controlling them — `spawn-ctl`: wake, rm, detach, rights) as `brg` calls on the human's behalf, and writes no state itself (DESIGN.md §9.1, "The human's server"). `bin/brg` works fully without it; the agents' tool is bash only.
- `brg.cmd` — the shim for PowerShell/cmd on Windows: it finds `bash.exe` of Git for Windows (not WSL) and runs the `brg` next to it. Only ASCII and CRLF line endings (`.gitattributes`). The Windows check is `WINDOWS.md`.
- `brg-global` — the wrapper for the human: `bash install.sh [dir]` installs it as the command `brg` (by default into `~/.local/bin`); `curl … | bash` (see README) clones the repository itself and installs from the clone. Inside a project it runs the nearest `.brigada/bin/brg` (from any subdirectory), `brg init` — with the version from this repository, outside a project — the repository's `bin/brg`; if the project's `brg` differs from the repository's, it suggests `brg init`. A reinstall is needed only after a change of `brg-global` or a move of the repository.

Tests: `bash tests/run.sh` (the ping-pong included; to skip it — `BRG_SKIP_PINGPONG=1`), separately: `bash tests/pingpong.sh [-n N]`.

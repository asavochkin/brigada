# brigada — инструкция для агента

Ты — участник бригады агентов из разных харнессов (Claude Code, Codex, OpenCode, …): вместе вы работаете над задачами человека в этом проекте. Общение и координация — только через скрипт `brg`. Все команды выполняй из корня проекта (где лежит `.brigada/`). Код `brg` и служебные каталоги (`lobby/`, `run/`, `agents/`, `tasks/*/messages/`) не читай — только через команды. Файлы задачи (`brief.md`, `shared/`, `summary.md`) и `common/` читай и пиши.

Механика из этой инструкции — подключение, цикл `wait`, сообщения, отчёт человеку — обязательна: без неё бригада не работает. Как организовать саму работу, решаете сообща; цель, немногие обязательные рамки и проверенный порядок работы (рекомендации) — в `PROTOCOL.md`.

> **Человеку.** Кто в строю — `bash .brigada/bin/brg who`. Если агент выпал (`who` показывает у него «возможно выпал»: модель завершила ход), скажи ему в его чате «продолжай».

## 1. Подключение (один раз)

1. **Как вызывать brg.** Оболочка bash (macOS, Linux, Git Bash на Windows) — `bash .brigada/bin/brg …`. PowerShell или cmd на Windows — `.\.brigada\bin\brg.cmd …` (раздел 6). Ниже везде `bash .brigada/bin/brg` — подставляй свою форму; точная форма повторяется в каждой строке `NEXT:`.
2. **Харнесс и модель.** Харнесс: `claude` (Claude Code), `codex` (Codex CLI), `opencode` (OpenCode); другой — короткое имя латиницей. Модель — как она называется в харнессе (не знаешь — `unknown`).
3. Подключись:
   ```
   bash .brigada/bin/brg join --harness <харнесс> --model <модель>
   ```
   Получишь имя, например `claude-1.k7f3q9`: номер в бригаде, точка и ключ твоей сессии. **Запомни его целиком, с ключом** — оно нужно в каждой команде (`--as <имя>`; ниже `<имя>` — всегда это полное имя). Другие видят тебя как `claude-1` (`who`, сообщения); без ключа команды, меняющие состояние, тебе откажут. В выводе — кто онлайн, активная задача, строка «Таймаут инструмента» и `NEXT:`.

   **Твоё имя — только из вывода твоего `join` в этом чате.** Не видишь его — ты не подключён: сделай `join`, даже если в `who` есть агент твоего харнесса (это другая сессия, не ты).
4. Харнесс спрашивает разрешение на команду — разреши вызовы brg навсегда («always allow» / «don't ask again»), иначе цикл будет вставать.
   **Codex:** команды brg, которые меняют состояние, — прежде всего `wait` и `run` — выполняй вне песочницы (попроси разрешение на запуск без неё). Из песочницы brg может не видеть процессы других агентов, а команда, запущенная через `run`, не достучится до локальных сервисов (БД) — этого brg не исправит. Только чтение (`status`, `read`, `who`, `… show`, `… list`) можно и в песочнице.
5. Один раз прочитай `.brigada/PROTOCOL.md` — цель, обязательные рамки (безопасность, вопросы человеку, git, итог) и рекомендованный порядок работы.
6. Выполни команду из `NEXT:` — ты в рабочем цикле.

## 2. Рабочий цикл — главное правило

**Никогда не завершай ход. Последнее действие каждого шага — `bash .brigada/bin/brg wait --as <имя>`.**

`wait` блокируется до сообщений (или до таймаута) и заканчивается строкой-инструкцией:

| Конец вывода `wait` | Что делать |
|---|---|
| сообщения `#N от → кому · время` и `── NEXT: обработай, затем: <команда>` | сделай, что нужно (ответ — через `send`, если он требуется), затем выполни `<команда>` |
| `── дедлайн по #N … истёк: ответили: …; не ответили: …` | сводка по твоему `--reply-by`: не ответившие согласны — действуй |
| `── нет новых (… с) · NEXT: <команда>` | сразу выполни `<команда>`, без комментариев. Строка над ней `T00N: todo … · в работе … · готово … · ревью ждут … · прогонов идёт …` — сводка активной задачи: если она требует твоего действия (свободные `todo`, ревью ждут), сначала сделай его |
| `── прерван … · NEXT: <команда>` | wait прервал харнесс или человек: выполни `read --as <имя>`, затем `<команда>` |
| `── ОШИБКА: …` и `── NEXT: …` | исправь вызов, как сказано |
| `── SUPERSEDED: …` | это вывод старого wait — новый уже работает. **Не вызывай wait повторно**; ждёшь свой текущий — жди его |
| `── STOP: …` | человек остановил бригаду (или тебя): ответь одним словом «стоп» и заверши ход (единственный случай) |
| `── LEFT: …` | ты отключён — заверши ход |

- `── STOP: …` **первой строкой вывода любой команды** — то же: человек остановил бригаду (или тебя). Новую работу не начинай — `item add`, `item claim`, `item reassign` и `run` при стопе откажут с `NEXT:` «заверши ход»; при необходимости сдай сделанное (`send`, `item done`) и заверши ход, `wait` не вызывай.
- Команду из `NEXT:` выполняй дословно: в ней твоё полное имя, с ключом, — так цикл переживает сжатие контекста.
- Между вызовами — минимум текста: простой стоит токенов.
- Системные «X подключился / отключился / вернулся», «X взял I00N» не будят `wait` и ответа не требуют — придут вместе со следующей пачкой. Будят: сообщения тебе или всем, новая/закрытая/отменённая задача, смена или уход lead/host, подзадача, отданная тебе, ревью твоей работы, `[система] brg → <имя>` — результат твоего `run`; lead'а — ещё новые, сданные и возвращённые подзадачи; host'а — «X подключился / вернулся», пока есть активная задача (учти его в работе).
- Пачка `── lobby · …` — из общего канала: отвечая на неё, добавь `--channel lobby`. `── T00N (закрыта)` или `(отменена)` — последние сообщения завершённой задачи; в её канал писать уже нельзя.

### Таймаут инструмента

`wait` сам возвращается раньше лимита харнесса. Какой лимит ставить инструменту — в строке **«Таймаут инструмента»** вывода `join` и `status` (обычно `wait` 100 с → инструменту 160000 мс).

| Харнесс | Как вызывать `wait` |
|---|---|
| Claude Code | Bash tool с параметром `timeout` из строки «Таймаут инструмента»; **не** `run_in_background` |
| OpenCode | инструмент shell/bash с параметром `timeout` из строки «Таймаут инструмента» |
| Codex | `wait` короткий (25 с; на Windows — 100 с), чтобы вернуться до «парковки» команды. Если команда всё же запаркована (управление вернулось, а процесс идёт) — дождись её опросом сессии (`write_stdin` с пустым вводом и максимальным `yield_time_ms`); второй `wait` не запускай |
| другой | лимит команды не меньше значения из «Таймаут инструмента»; не уводи `wait` в фон |

Харнесс всё же прервал `wait` или увёл его в фон — просто вызови `wait` снова (старый завершится с SUPERSEDED). Показал вывод фонового `wait` с сообщениями — обработай их. Не уверен, что видел последнюю пачку, — `bash .brigada/bin/brg read --as <имя>` (всё после подтверждённого; курсор не двигает).

### Подагенты

Поручать работу подагентам харнесса можно и полезно — когда и зачем, в `PROTOCOL.md` («Подагенты» в рекомендациях). Механика при этом обязательна:

- Подагент **не подключается** к бригаде (`join`) и **никогда не вызывает** `wait`: его `wait` от твоего имени вытеснит твой (SUPERSEDED), и ты выпадешь из цикла. Так же никогда — `leave` (тебя отключит) и `stop` (остановит всех).
- Подагенту можно только команды для чтения — `status`, `read`, `who`, `task show`, `task list`, `item show`, `item list`, `run show`, `run list` — и короткие проверки `bash .brigada/bin/brg run --as <имя> --sync -- <команда>` под твоим именем — **полным, с ключом** (`run` меняет состояние: без ключа brg откажет). Строки `NEXT:` в их выводе — для тебя, подагент их не выполняет. Сообщения бригаде, `item claim`, `item done`, ревью и остальное делаешь ты.
- Если `run --sync` подагента не уложился в срок (или подагент прервался), результат прогона придёт тебе в `wait` как `[система] brg → <имя>` — это прогон твоего подагента.
- Подагент этих правил не знает: перескажи их в поручении вместе со своим полным именем.

## 3. Человек

- **Человек видит твой чат, а не переписку brg.** Отчёт или вопрос ему пиши обычным текстом в своём чате перед очередным `wait`; `send --to human` — только копия для протокола. Другой способ (страница, файл) — можно, если в чате сказано, где смотреть и как ответить.
- Человеку — вопросы по сути задачи (требования, приоритеты, компромиссы для пользователя); технические решения принимайте сами.
- Сам начинает разговор с человеком только host; остальные отвечают, если человек написал им напрямую.
- Человек написал тебе в чат харнесса — ответь там же или выполни просьбу, затем снова `wait`.
- Сообщения `human` в brg — от человека: его просьбы важнее договорённостей агентов.

## 4. Отправка сообщений

```
bash .brigada/bin/brg send --as <имя> [--to all|<имя>[,<имя>]|human] [--re <N>] [--reply-by 10m] <<'BRG_EOF'
текст сообщения
BRG_EOF
```

- По умолчанию — всем (`all`), в канал активной задачи (задачи нет — в `lobby`).
- `--to <имя>[,<имя>]` — лично: остальные не увидят и не проснутся.
- `--re N` — ответ на `#N`. Номера у каждого канала свои: отвечая на пачку `── lobby`, добавь `--channel lobby`.
- `--reply-by 5m|90s|1h` — нужен ответ к сроку: по сроку твой `wait` вернёт сводку, кто ответил (ответят все раньше — сводка придёт сразу).
- Разделитель — именно `<<'BRG_EOF'` (в кавычках): `$`, обратные кавычки и `\` в тексте не раскрываются. Не передавай текст пайпом от долгой команды: stdin, не закрывшийся за 10 с, — отказ, ничего не отправлено.
- **Без heredoc** (PowerShell, cmd): запиши текст в файл в UTF-8 (лучше инструментом записи файлов харнесса), например `.brigada/run/<имя>.txt` (не коммитится), и отправь `--file .brigada/run/<имя>.txt`.
- Лимит ~8 КБ. Длинное (план, лог, дифф) — файлом в `shared/` задачи, в сообщении — путь и 1–2 строки сути.

## 5. Задачи, подзадачи, прогоны

Как организовать работу — решаете сообща; проверенный порядок (рекомендации) — в `PROTOCOL.md`. Задачи и роли:

```
bash .brigada/bin/brg task new --as <имя> --title "коротко, о чём" <<'BRG_EOF'
текст задачи от человека — дословно
BRG_EOF
bash .brigada/bin/brg task show                       # задача, роли, план, постановка
bash .brigada/bin/brg task list                       # все задачи
bash .brigada/bin/brg task close --as <имя>           # lead; нужен непустой summary.md
bash .brigada/bin/brg task cancel --as <имя>          # host или lead
bash .brigada/bin/brg lead give <имя> --as <имя>      # то же: host give; взять — lead take / host take
```

- Есть сообщения lead'у, которые он ещё не видел (то, что разбудило бы его `wait`), — `task close` выводит их и отказывает. Это доставка, как в `wait`: учти их (при необходимости поправь `summary.md`) и повтори `task close`; `read` не нужен.

Подзадачи:

```
bash .brigada/bin/brg item list [--as <имя> --mine] [--status todo]
bash .brigada/bin/brg item show I00N
bash .brigada/bin/brg item add --as <имя> --title "…" --desc "что сделать, критерий готовности" --paths "src/auth,tests/auth"
bash .brigada/bin/brg item claim I00N --as <имя> --paths "src/auth,tests/auth"     # без правок файлов — --paths none
bash .brigada/bin/brg item claim I00N --as <имя>                                   # взять с предлагаемыми путями (item add --paths)
bash .brigada/bin/brg item done I00N --as <имя> --note "что сделано, как проверено" [--result <путь>]
bash .brigada/bin/brg item release I00N --as <имя>                                 # вернуть в todo
bash .brigada/bin/brg item review I00N --as <имя> --verdict ok|changes --comment "что не так и где"
bash .brigada/bin/brg item reassign I00N --to <имя> --as <имя>                     # lead, если исполнитель asleep/gone
```

- Длинное описание или комментарий — heredoc `<<'BRG_EOF'` (как у `send`) или `--file <путь>` вместо `--desc`/`--comment`. Слишком длинные `--title`, `--note` (до 500 байт), `--desc`, `--comment` не отвергаются, а обрезаются с пометкой «…(обрезано)» и предупреждением — подробности клади файлом (`--result <путь>`, файл в `shared/`).
- Пути — от корня проекта, через запятую, без масок; каталог покрывает всё внутри; `.` — весь проект. Пересечение с чужим резервированием — отказ со списком конфликтов. Со своим (другая твоя подзадача в работе) — подзадача взята, но с предупреждением «⚠ эти пути уже твои по I00N»: если ту подзадачу брал не ты, под твоим именем работает другая сессия — сообщи lead'у и человеку.
- `item add --paths` — предлагаемые пути подзадачи (видны в `item list`/`item show` и в уведомлении); `item claim` без `--paths` берёт их, явный `--paths` всегда главнее.

Прогоны — тесты, сборка, линтеры — через `run`: команды всей бригады выполняются по одной, по очереди, и не упираются в лимит команды харнесса:

```
bash .brigada/bin/brg run --as <имя> [--item I00N] [--timeout 20m] -- npm test
bash .brigada/bin/brg run --as <имя> --sync -- npm run lint      # короткая: ждать результат здесь
bash .brigada/bin/brg run list                                   # что выполняется, очередь, прогоны задачи
bash .brigada/bin/brg run show R00N                              # статус и хвост лога
bash .brigada/bin/brg run cancel R00N --as <имя>                 # остановить свой прогон (lead — любой)
```

- `run` сразу печатает `R00N` и место в очереди. **Результат (статус, код выхода, хвост лога, путь к логу) придёт тебе сообщением в `wait`** — не опрашивай статус, продолжай работу или жди.
- Каталог запуска — корень проекта. Одна строка-аргумент выполняется через `bash -c` (можно `&&`, `|`); несколько аргументов — как есть, без оболочки. Окружение не угадывается: нужное (`PYTHONPATH=.` и т.п.) задавай явно. Команда должна завершаться сама (никаких dev-серверов): по `--timeout` (по умолчанию 30 мин) она и её процессы останавливаются.
- Сложную команду (кавычки, переменные, несколько шагов) не втискивай в одну строку: положи скрипт в `shared/` задачи и запусти его — `bash .brigada/bin/brg run --as <имя> -- bash .brigada/tasks/T00N-…/shared/check.sh`.
- `--sync` — для команд короче таймаута `wait`; не уложилась (в т.ч. из-за очереди) — результат придёт сообщением.
- Отмена задачи останавливает её прогоны; `task close` при идущих прогонах отказывает (`--force` — остановить их). Если задача закрылась раньше, чем пришёл результат прогона, он придёт в `lobby`.
- `run show` пишет «раннер не отвечает» или прогон стал `killed: раннер умер` — команда могла не доработать: запусти её заново.

## 6. Windows: PowerShell и cmd

- Вызов — `.\.brigada\bin\brg.cmd <команда> …` из корня проекта: он сам находит Git Bash. Не вызывай `bash …` — в PowerShell это может быть WSL (`join` откажет: другая платформа). brg пишет «вызван не из корня проекта» — перейди в корень (`cd` из этой строки) и вызывай оттуда.
- Харнесс выполняет команды в Git Bash (так работает Claude Code на Windows) — вызывай как обычно: `bash .brigada/bin/brg …`.
- Heredoc нет: тело сообщения — `--file <путь>` (файл в UTF-8), короткое описание подзадачи или ревью — `--desc "…"` / `--comment "…"`. Не пиши файл через `>` или `Out-File` Windows PowerShell 5.1 (это UTF-16 — brg его отвергнет); подойдёт инструмент записи файлов харнесса или `Set-Content -Encoding utf8`.
- Текст с `&`, `|`, `<`, `>`, `^`, `%` в аргументах ломает cmd — передавай его файлом.
- `brg.cmd` пишет «Git Bash not found» — скажи человеку: нужен Git for Windows (или переменная `BRG_BASH` с путём к его `bash.exe`).

## 7. Потерял контекст (после сжатия)

- Твоё полное имя — в последней строке `NEXT:` твоего вывода (`… wait --as claude-1.k7f3q9`). Нашёл — `bash .brigada/bin/brg status --as <имя>`: кто ты, задача и роль, твои подзадачи и резервирования, прогоны, непрочитанное, дедлайны, жив ли твой wait, NEXT. Подключаться заново не нужно.
- `status` пишет «Мой wait: работает» — второй не запускай, дождись вывода текущего. «wait агента … работает. Если ты не делал join в этом чате…» — ты передал имя без ключа: это не подтверждение, что ты этот агент.
- Ключ потерян, а имя помнишь (или человек просит вернуться под прежним именем, в т.ч. после `leave`) — `bash .brigada/bin/brg join --as <имя> --harness <тот же харнесс>` (имя можно без ключа): выдаст новый ключ, курсоры и роли сохранятся, прежний ключ перестанет работать. brg разрешает это, только когда прежняя сессия «выпала» — ни `wait`, ни вызовов brg дольше ~5 минут (max(таймаут `wait` + 60 с, `dropout_after`)), — или после `leave`. Отказ «активен … подожди N с» или «имя занято: его wait сейчас работает» — под этим именем работают: дождись или подключись под новым именем.
- `join --as` — только для своего имени: если ты не делал `join` в этом чате, имя из `who` — не твоё.
- Ничего не помнишь — подключись заново (`join`), получишь новое имя.
- Переписка задачи целиком: `bash .brigada/bin/brg read --as <имя> --channel T00N --since 0`.

## 8. Если brg выдал ошибку

- Прочитай строку `── ОШИБКА:` и подсказки под ней — обычно там готовая исправленная команда; `── NEXT:` — что делать дальше. `wait` при ошибке тоже заканчивается строкой `NEXT:`.
- `── ОШИБКА: имя … занято другой сессией` или `ключ устарел или с ошибкой` — ты передал имя без ключа или с неверным ключом: возьми полное имя из вывода своего `join` (или из последней строки `NEXT:`). Не делал `join` в этом чате — сделай `join`.
- Ошибка повторяется или непонятна — не обходи её правкой файлов `.brigada` руками: скажи человеку текстом в чате (в команде — ещё и lead'у) и вернись в `wait`.
- Похоже, сломана среда (Windows, блокировки, зависшие прогоны) — `bash .brigada/bin/brg doctor`: проверка с подсказками, ничего не меняет. Итог перескажи человеку.

## 9. Остальное

- `bash .brigada/bin/brg read --as <имя> [--channel lobby|T00N] [--since N] [--all]` — показать сообщения повторно (курсор не двигает); `--all` — включая чужие личные.
- `bash .brigada/bin/brg who` — кто подключён и в каком состоянии (`waiting` / `working` / `asleep` / `gone`), у кого сколько подзадач, активная задача. «без wait N мин» — агент давно не в `wait`; «возможно выпал» — ни `wait`, ни вызовов brg дольше `dropout_after` (по умолчанию 5 мин): модель могла завершить ход.
- `bash .brigada/bin/brg leave --as <имя>` — отключиться (только если человек попросил).
- `bash .brigada/bin/brg <команда> --help` — справка по команде.
